# Pi 记忆集成与子代理生命周期接缝（研究笔记，2026-08-21）

> 主题：为「Pi-only agentbrain adapter」可行性研判，盘点 Pi（@earendil-works/pi）宿主的稳定接缝，与 pi-astack 的私有约定区分开。
> 证据基础：上游 Pi 官方文档与源码 `earendil-works/pi@5cd93f688aaab89dbb6dfa4aca535f21796ae185`（`main`，2026-08-21 固定）+ 本地只读参考 `~/code_me/pi-astack@ad6aa8f8ba15a86af63e351e1fc9934dff3c72ac`（Pi 包 pinned `0.83.0`，peer `>=0.80.10 <1.0.0`，见 `~/code_me/pi-astack/package.json:346-355`）。
> 边界提醒：当前 agentbrain v1.2 仍把 Pi 排除在范围外（`docs/design/20260804-agentbrain-总体设计.md:184`）；Wayfinder 已决定 v2 改为 Pi-only。本笔记只提供事实接缝，不构成 v2 实现授权。

## 0. 一句话结论

Pi 的**事件面、会话 JSONL、工具注册、提示注入**是文档化的公开契约，agentbrain adapter 可以直接依赖；**子代理（subagent）不是 Pi 概念**——它是 pi-astack dispatch 扩展的私有构造（SDK in-process 二级会话 + WeakSet 标记 + 自造因果锚点），任何「主/子代理区分、轮次级因果身份」在 Pi 公开 API 里都不存在，adapter 若需要必须自建或显式对齐 pi-astack 私有约定。

## 1. 会话/轮次/代理生命周期事件（公开、稳定）

来源：`packages/coding-agent/src/core/extensions/types.ts` 的 `ExtensionEvent` 联合类型（upstream），与官方 `docs/extensions.md` 一致。

- 会话级：`session_start`（`reason: "startup"|"reload"|"new"|"resume"|"fork"`，带 `previousSessionFile`）、`session_shutdown`（`reason: "quit"|"reload"|"new"|"resume"|"fork"`，带 `targetSessionFile`）、`session_info_changed`、`session_before_switch`、`session_before_fork`、`session_before_tree`、`session_tree`。
- 代理/轮次级：`before_agent_start`（payload：`prompt`、`images`、`systemPrompt`、`systemPromptOptions`；可返回 `{ systemPrompt, message }` 改写注入）、`agent_start`、`agent_end`（`messages`）、`agent_settled`（重试/压缩/队列全部排空后才发）、`turn_start`/`turn_end`（`turnIndex`、`message`、`toolResults`）、`message_start`/`message_update`/`message_end`。
- 工具级：`tool_call`（可改 `input`、可 block）、`tool_result`（中间件链式改写）、`tool_execution_start`/`tool_execution_update`/`tool_execution_end`、`user_bash`。
- 模型级：`before_provider_headers`、`before_provider_request`、`after_provider_response`、`model_select`、`thinking_level_select`。
- 上下文级：`context`（LLM 调用前过滤/调整 messages，返回 `{ messages }`）。
- 启动级：`project_trust`、`resources_discover`。

语义要点（对记忆管线关键）：
- `agent_end` = 一次用户提交的完整运行结束（含全部工具轮）；`turn_*` 是其**内层**工具调用轮。pi-astack 的 sediment 以 `agent_end` 为沉淀触发（`extensions/sediment/index.ts:7201`），官方保证「pi awaits agent_end listeners before agent_settled」（sediment/index.ts:7219 注释引述）。
- `turnIndex` 每个 `agent_start` 重置为 0（pi-astack 在 `core/agent-session.js:351` 验证，见 `extensions/_shared/causal-anchor.ts` 头注）——**它不是用户级轮次号**。
- 多个扩展的 `before_agent_start` 返回值会被 Pi 链式合并（pi-astack memory 依赖此行为做幂等 marker 注入，`extensions/memory/index.ts:786-960` 注释明言 "pi chains systemPrompt return values from all handlers"）。

## 2. 标识符（session / branch / turn / causal）

公开契约（`docs/session-format.md`）：
- 会话头：`{"type":"session","version":3,"id":"<uuid>","timestamp","cwd"[,"parentSession":"<path>"]}`。`parentSession` 仅在 `/fork`、`/clone`、`newSession({parentSession})` 时出现——**会话文件级**的血缘，非轮次级。
- 条目树：每个 entry 有 `id`（8 位 hex）、`parentId`（首条为 null）；分支切换产生 `branch_summary` 条目（`fromId` 指向分叉点）；`label` 条目可做书签。
- 工具调用：`toolCallId` 贯穿 toolCall→toolResult。
- 环境变量（每条 bash 命令注入，`docs/environment-variables.md`）：`PI_SESSION_ID`、`PI_SESSION_FILE`（ephemeral 会话为 unset）、`PI_PROVIDER`、`PI_MODEL`、`PI_REASONING_LEVEL`；进程级标记 `AI_AGENT=pi`、`PI_CODING_AGENT=true`。

**缺口**：Pi 没有用户级 turn id，也没有跨会话委托（delegation）id。pi-astack 因此自造 `CausalAnchor { session_id, turn_id, subturn?, sub_agent_label? }`（`extensions/_shared/causal-anchor.ts:62-71`）：`turn_id` 由自己在 `before_agent_start` 递增（每用户提交 +1，跨会话单调），`subturn` 在 dispatch 派发子任务时分配，**不改写父锚点**以保证 join key 稳定。锚点解析失败时 fail-open（`getCurrentAnchor()` 返回 undefined，日志照写）。

## 3. Transcript 访问与压缩（公开、稳定）

- 存储位置：`~/.pi/agent/sessions/--<cwd路径>--/<timestamp>_<uuid>.jsonl`（可用 `--session-dir` / `PI_CODING_AGENT_SESSION_DIR` 覆盖）。v3 格式，旧版自动迁移。
- 扩展内读取：`ctx.sessionManager`（`getEntries()`、`getBranch(fromId?)`、`buildContextEntries()`、`buildSessionContext()`、`getTree()`、`getLeafId()`、`getLabel()`）；SDK 侧 `session.messages` / `SessionManager.list()/listAll()/open()`。
- 外部读取：JSONL 是纯文本可直接解析；RPC 模式 `get_entries` 支持 `since: <entryId>` 作为**跨重启的持久游标**（`docs/rpc.md`）——对「取本分支最近 N 轮」的 TranscriptEntry adapter 非常合适。
- 扩展自有状态：`pi.appendEntry(customType, data)` 写 `custom` 条目（**不进 LLM 上下文**），`session_start` 时沿 `getBranch()` 重建——这是官方推荐的分支安全状态存储。
- 压缩（`docs/compaction.md`）：自动触发 `contextTokens > contextWindow - reserveTokens`（默认 16384；`keepRecentTokens` 默认 20000）；`/compact` 手动。切点规则：user/assistant/bashExecution/custom 消息可切，toolResult 永不与 toolCall 分离。`CompactionEntry { summary, firstKeptEntryId | retainedTail[], tokensBefore, usage?, details?, fromHook? }`。扩展可挂 `session_before_compact`（`return { cancel: true }` 或提供自定义压缩结果，payload 含 `messagesToSummarize`、`previousSummary`、`reason: "manual"|"threshold"|"overflow"`、`willRetry`）与 `session_compact_failed`。压缩后 transcript 的 L1 证据语义：`buildContextEntries()` 只沿当前 leaf→root 路径并尊重压缩检查点——**离线读 JSONL 时必须自己做等价的分支+压缩重建**，否则会读到已被压缩吞掉的历史（agentbrain 的 pi transcript adapter 要点）。

## 4. 上下文/提示注入（公开、稳定）

四条互不冲突的通道：
1. **文件层**：`AGENTS.md`/`CLAUDE.md`（`~/.pi/agent/` → 父目录向上 → cwd，`AGENTS.override.md` 可替换单层）；`.pi/SYSTEM.md` / `~/.pi/agent/SYSTEM.md` 整体替换系统提示，`APPEND_SYSTEM.md` 追加。**agentbrain 的 marker 块方案（设计 §3）在 Pi 上零适配可用**——写 AGENTS.md 即可。
2. **事件层**：`before_agent_start` 返回改写后的 `systemPrompt`（pi-astack memory 的 Path A「每轮相关性注入」和 memory-footnote 协议块都走这条路，`extensions/memory/index.ts:786,908`）；也可注入 `message`。注意首条消息时 `before_agent_start` 的 ctx 尚缺 `modelRegistry`（pi-astack 在 `session_start` 先捕获，`memory/index.ts:897-913`）。
3. **消息层**：`pi.sendMessage(content, { deliverAs: "steer"|"followUp"|"nextTurn", triggerTurn })` / `pi.sendUserMessage`；`custom_message` 条目进 LLM 上下文（`display` 控制可见性）。
4. **过滤层**：`context` 事件在每次 LLM 调用前过滤 messages（pi-astack 用 pi-internals 里的 `buildSessionContext` 内部 API 做同类事的强化版，属私有）。

缓存注意：pi-astack 把易变注入包 `wrapVolatile` 由 time-injector 提到 prompt 尾部以保前缀 cache 命中（memory/index.ts Path A 注释）——agentbrain 注入层若走 `before_agent_start` 应遵循同样的「稳定前缀、易变后缀」纪律。

## 5. 工具/命令注册（公开、稳定）

- `pi.registerTool({ name, label, description, promptSnippet, promptGuidelines, parameters(typebox), prepareArguments?, execute, renderCall?, renderResult? })`；枚举必须用 pi-ai 的 `StringEnum`（Google 兼容）；`execute` 抛错=`isError`；输出必须截断（内置上限 50KB/2000 行）。`memory_search` / `abrain_get` / `memory_decide` 即此模式。
- 可覆写内建工具（read/bash/edit/write/grep/find/ls 是**全部**内建面，见 upstream `src/core/tools/` 目录）；动态加载支持 Anthropic `defer_loading` 与 OpenAI `tool_search`，但仅允许增量 `setActiveTools`。
- `pi.registerCommand(name, { handler, getArgumentCompletions })`，重名自动加后缀 `/name:1`；`pi.registerFlag` + `pi.getFlag`。

## 6. 主会话 vs 子代理：公开 API 不存在，全是 pi-astack 私有约定

上游证据（三条独立佐证）：
- 内建工具仅 read/bash/edit/write/grep/find/ls，无 task/dispatch 类工具（`src/core/tools/` 目录清单）。
- agent-core 的 `AgentEvent` 联合类型无任何 parent/nested/delegation 字段（`packages/agent/src/types.ts`）。
- `src/core/extensions/types.ts` 无 subagent 相关类型；SDK 文档明言「不提供嵌套 pi 生成 API」，子进程集成只有 RPC（`pi --mode rpc --no-session`）与 in-process `createAgentSession()` 两条路。

pi-astack 的私有构造（**adapter 不得默认依赖，除非显式对齐**）：
- dispatch v3（2026-05-23）：放弃子进程方案（v2 的孤儿进程/双层超时/临时文件/输入历史污染全部是痛点，`extensions/dispatch/index.ts:4-22`），改为 in-process `createAgentSession()` + `SessionManager.inMemory()`（子代理**不落盘**会话文件）+ 共享父 `modelRuntime`（`dispatch/index.ts:2083-2110`）。
- 主/子区分：`markSessionAsSubAgent(subAgentSm)` 在 `createAgentSession` **之前**打标（因为 pi 在会话构造内同步发 `session_start`）；通道是 SessionManager 上的 WeakSet + globalThis id 注册表（`extensions/_shared/pi-internals.ts`）。sediment/memory/compaction-tuner/model-fallback 等全部用 `isSubAgentSession(ctx)` 跳过主会话专属副作用；sediment 对「边界不可信」的 agent_end 直接拒绝写入（`sediment/index.ts:4142`），且子代理 toolResult 被 P0-α 掩蔽、不作为学习信号（`memory/index.ts:760-830` 注释）。
- 版本脆弱性实证：dispatch 依赖的 SDK 签名在 0.75→0.80.10 间已变过两次（`ToolDefinition.prepareArguments` 类型收紧、`createAgentSession` 改收 `modelRuntime`，`dispatch/index.ts:118,2099` 注释）——in-process SDK 集成的漂移成本真实存在。

## 7. 父子/委托血缘

- 公开：只有会话文件级 `parentSession`（fork/clone）+ 条目树 `parentId`/`fromId`。轮次级委托血缘无。
- pi-astack 私有：causal anchor 注入子代理 prompt + dispatch 审计日志；实现上因 Pi 的 jiti 扩展加载器对每个扩展用独立 `moduleCache:false` 实例（每个扩展拿到 `_shared/*` 的**独立模块副本**），共享状态必须放 `globalThis[Symbol.for("pi-astack/causal-anchor/state/v1")]`（`causal-anchor.ts:88-140`，R4 修复注记）。**这是 Pi 扩展运行时的真实约束，任何多扩展共享状态的 Pi adapter 都会踩到。**

## 8. 扩展存储

- 公开：`~/.pi/agent/`（`PI_CODING_AGENT_DIR` 可覆盖）下 settings.json / models.json / auth.json / trust.json / extensions/ / sessions/；项目侧 `.pi/extensions/`、`.pi/skills/`、`.agents/skills/`；SettingsManager「项目覆盖全局、嵌套键合并」。会话内状态官方路径是 `custom` entry（见 §3）。
- pi-astack 私有：自有 `~/.abrain/` 八区（identity/skills/habits/workflows/projects/knowledge/vault/rules，`extensions/abrain/brain-layout.ts:5-38`）+ 独立的 `~/.pi/agent/pi-astack-settings.json`（**不在官方 settings 链内**，UPSTREAM.md §2）。agentbrain v2 的物理 store 尚未冻结；运行时不得与 `~/.abrain` 形成双主。未来是否单向导入其非敏感资产，必须在 L1/L2/隐私合同关闭后另行取得只读授权。

## 9. 后台任务/进程生命周期

- 公开纪律（`docs/extensions.md`）：不要在扩展工厂里起后台资源（非会话调用也会跑工厂）；在 `session_start` 启动、`session_shutdown` 幂等关闭；`ctx.signal` 是代理中止信号。
- 关键坑（pi-astack 实证）：**print 模式进程在 `agent_end` 后即退出**，agent_end 里 detach 出去的后台工作会死（`sediment/index.ts:5344-5356` 注释）。sediment 的对策是 durable intake 落盘 + 下次 session_start/agent_end 恢复，而不是硬保活。agentbrain 的「Stop hook detached 拉起 `claude -p`」模式在 Pi 上等价物是 `agent_end`/`session_shutdown` 里 detached spawn `pi --mode json` 子进程——**必须验证 print/json 模式下 detached 子进程能否在父退出后存活**（throwaway prototype 项）。
- dispatch 对子代理的看护（timeout 30min 无进度、max runtime ×4、heartbeat、abort 信号双检）全部是私有实现（`dispatch/index.ts:133-137,2060-2130`）。

## 10. 模型调用

- 公开：`ctx.modelRegistry`（扩展兼容门面）/ SDK `ModelRuntime`（凭证优先级 runtime → auth.json → 环境变量）；pi-ai 直接 `getModel`/`createProvider`；嵌套 LLM 调用的 usage 记在 toolResult `usage` 字段做记账；`before_provider_request` 可改写请求。
- pi-astack 实际用法：`modelRegistry.find(provider, modelId)` + `getApiKeyAndHeaders(model)` + `@earendil-works/pi-ai/compat` 的 `streamSimple`（`extensions/sediment/constraint-compiler/pi-ai-invoker.ts:57-77`，带 timeoutMs/maxRetries/AbortSignal）。这是「宿主内借宿主凭证做沉淀算力」的现成范式，与 agentbrain 设计 §8 的 worker LLM adapter 议题直接对应（Pi adapter 可走 in-扩展调用而无需独立 key）。

## 11. 失败/降级行为

- 消息级：`AssistantMessage.stopReason ∈ stop|length|toolUse|error|aborted` + `errorMessage`；流式 `pending` 不会落盘。自动重试事件 `auto_retry_start/end`（RPC 可 `set_auto_retry`）。
- 压缩级：`session_compact_failed { reason, errorMessage, aborted, willRetry, fromExtension }`；`summarization_retry_*` 事件序列。
- 扩展级：RPC 协议提供 `extension_error` 事件，但本轮读取的公开文档片段不足以证明“任意 extension listener 抛错都不会影响主循环”这一全局合同；只能确认部分 renderer/transformer 有局部错误隔离。Pi adapter 不应依赖未经源码测试验证的全面 fail-open。pi-astack 自身的纪律是「观测优先于完整性」：锚点缺失照写日志、agent_end 快速返回（p99<100ms capture 合同）+ 异步队列消化。
- 与 agentbrain 的对齐点：设计 §6.1 的显式分级降级（embedding 缺→sparse-only、LLM 缺→返回候选并标注）与此同哲学，Pi adapter 直接沿用，不抄 abrain 的 hard-error 合同。

## 12. Pi-only agentbrain adapter：可依赖 / 需原型 / 不得泄漏

**可直接依赖（公开契约）**：
- 生命周期挂点：`session_start`（注入/恢复）、`before_agent_start`（marker 块 + 相关性注入）、`agent_end`（capture 触发，快速返回）、`session_shutdown`（清理）。
- transcript：会话 JSONL 直读（含 `PI_SESSION_FILE` 定位）或 SDK `SessionManager`；RPC `get_entries since=<entryId>` 做增量游标。
- 注入：AGENTS.md marker 块（宿主指令文件方案零改动）+ `before_agent_start` systemPrompt 链。
- 工具面：`agentbrain search` / `get` 以 `registerTool` 注册，`StringEnum` + 截断纪律照抄 pi-astack 参数面。
- 算力：`modelRegistry` + pi-ai `streamSimple` 借宿主凭证跑精排（对应设计 §6.1 Tier2 的 Pi 落地形态）。

**必须 throwaway prototype 验证（Pi 行为未文档化或已漂移）**：
1. print/json 模式 `agent_end` 后 detached 子进程存活性与输出落盘（sediment 的 durable-intake 对策暗示这是真实风险）。
2. 用户级 turn id 方案：自造（causal-anchor 式 `before_agent_start` 计数 + globalThis Symbol.for 共享）还是改用 entry id 派生——两案都要过 jiti 多扩展隔离这一关。
3. 「取本分支最近 N 轮 + 压缩检查点重建」的离线 JSONL 解析正确性（对照 `buildContextEntries()` 语义）。
4. in-process SDK（`createAgentSession`）签名漂移监控成本 vs RPC 子进程方案的稳定性（dispatch v2→v3 的教训清单就是验收表）。
5. `before_agent_start` 首轮 ctx 缺 `modelRegistry` 的规避（session_start 捕获）。

**不得泄漏进记忆域（宿主私有，只许活在 adapter 层）**：
- pi-astack 的 `isSubAgentSession` WeakSet 标记、causal anchor join-key、dispatch governor/heartbeat、`~/.abrain` 八区、pi-astack-settings.json、audit JSONL 约定——这些只能作为 Pi adapter 或迁移来源的外部事实，不能成为 agentbrain canonical domain 类型。
- Pi 内部 API（pi-internals.ts 里的 `buildSessionContext`、`prepareNextTurn`、`_emit` 等）：pi-astack 自带启动完整性检查 + 优雅降级来兜版本漂移，agentbrain adapter 不应引入同类依赖；需要同等能力时走公开事件面。
- 若未来要与 pi-astack 共存于同一 Pi 实例（用户同时装两套），需额外约定互不注入冲突（marker 块前缀区分）——本轮未验证，列为风险项而非结论。
