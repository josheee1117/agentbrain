# 5. 价值标准抽取门（PR #51 A 部分，2026-10-14）

## 问题
把抽取提示词按"好记忆的 7 条标准"重写，并加确定性校验：场景必填（"当…时"）、阶段性内容丢弃、代码里能查到的丢弃、叙事口吻丢弃。这样能不能在**抽取时**就挡住没用的记忆，同时不丢有用的？

## 数据
- **sample30**（`eval/value-gate/sample30.{json,md}`，`labels30.json`）：从真实库 active 条目里抽 30 条，**用户逐条标**"有用 / 部分有用 / 没用"。抽样脚本是 `gen.py`，它读的 `raw_sample.json` 含原始引文，没有提交。`.md` 是给用户标注时看的版本，已脱敏。
- **fresh30**（`labels_fresh30.json`）：另抽 30 条，种子 20261015。由执行者在跑任何评测**之前**标注，只作参考。
- 复判输入是 `gate_items.json`：每条带当时的证据片段和项目。
- Pensieve 导入的条目不经过抽取，PR 里的主口径把它们排除，剩 n=41（有用 20、没用 21）。下表"全部 60"一栏没有排除导入条目。

## 方法
- **复判**（`gate.ts <repo> <items.json> <old_extract.ts> <out.json>`）：把同一份复判输入分别交给旧版和新版抽取提示词（各自带自己的 validate），模型是 Ark 的 deepseek-v4.1-flash，看这条还会不会被记。打分用 `score.py <out.json>`。
- **窗口重放**（`replay.ts <new_repo> <base_repo> <store_dir> <items.json> <out.json>`，打分用 `rscore.py`）：用条目当初的原始会话窗口重跑抽取。需要库副本和转录，没有提交。
- 基线：这 60 条在存量库里是 60/60 全部入库，没用的一条都没被拒。

## 结果

PR #51 主口径（n=41，不含导入）：

| 提示词 | 有用保留 | 没用拒掉 |
|---|---|---|
| 旧 | 10–11/20 | 11–12/21 |
| 新 v2（两次运行） | 10/20、9/20 | 19/21、19/21 |

全部 60 条（含导入，`score.py` 输出）：

| 运行 | 旧：有用保留 / 没用拒掉 | 新：有用保留 / 没用拒掉 |
|---|---|---|
| gate_out_v1（新提示词 v1） | 16/38 / 12/22 | 14/38 / 14/22 |
| gate_v2a | 15/38 / 12/22 | 11/38 / 20/22 |
| gate_v2b | 15/38 / 13/22 | 12/38 / 20/22 |

窗口重放 v1（26 个能找回窗口的条目）：新旧准确率都是 0.50，噪声很大。v2 重放中途中断，没有跑完。

## 结论与决定
- 新提示词挡没用的效果很明显（约 55%→90%），但有用的保留率也一起下降（约 50%→45%）。在抽取这一步"一次判死"太粗。
- 2026-10-14：#51 关闭不合并。B（worker 派活提示不算用户原话、`ab audit worker-quotes`）和 C（常驻偏好块）拆成 #52、#53 合并。A 的标准改为在 v3 里使用：抽取结果先进候选区，再由审稿模型按《好记忆的标准》判断去留（见第 6 篇）。

## 保留意见
- 每类只有 20 条左右，1 条约 5 个百分点。
- 复判输入是"条目 + 证据片段"，不是完整的会话窗口，比真实抽取场景信息少。
- 用户标注只有 sample30。
