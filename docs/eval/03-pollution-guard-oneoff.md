# 3. 防记错：引文归属与一次性授权（PR #40 → 独立评估 → #43～#46，2026-10-14）

## 问题
#40 在抽取准入处加了两道确定性拦截：
- 用户引文必须是用户自己写的字（`ownUserText`：去掉代码块、标签块、`>` 引用行）。
- 只是一次性授权的 rule/decision 丢弃（`isOneOffAuthorization`）。

需要回答两个问题：它们误杀多少有价值的决定？漏拦多少一次性授权？

## 数据
- **独立评估样本 sample48**（`eval/oneoff/sample48.json`）：独立评估者从 91 个会话、246 个去重用户轮里挑出 48 条短消息，逐条人工标 `oneOff`。其中 11 条当时被规则判中，37 条像授权但没判中。修复时有 2 条标签改成"不是一次性"（认可助手方案的话算决定），见 #43。
- **留出集 heldout160**（`eval/oneoff/heldout160.json`）：从 Mac 转录里新抽 160 条用户消息，和 sample48 不重叠。由执行者**在跑任何代码之前**先标注，定义写在文件头。前 80 条是随机主样本。
- **真实库回放**：Mac 库副本里所有带用户引文的 rule/decision（active 107、archived 140，302 处引文），用 sha256 反查原文。回放数据含转录原文，没有提交；结论在 `eval/oneoff/eval-40-42-review.md`。

## 方法
- 规则单测式打分：
  ```bash
  node eval/oneoff/score.ts <repo>/src/extract.ts        # sample48：P/R、误判和漏判清单
  node eval/oneoff/score-held.ts <repo>/src/extract.ts   # heldout160：first80 和 all160
  ```
- 真实库回放：新旧两版 `ownUserText` 和 `isOneOffAuthorization` 逐条重判，数 active 条目里的误拦。
- 独立评估报告：`eval/oneoff/eval-40-42-review.md`，同时评了 #41（纠正必带）和 #42（过期复审）。

## 结论与决定
- 2026-10-14 独立评估结论：#40 要修，不回滚。误杀的代价（丢掉有价值的决定）比漏拦大，漏拦还有提示词和后续确认兜底。
- 10:52 合并 #43：问答卡片回答和 `<command-args>` 算用户的话；去掉"这个/这条"标记；短授权必须整句匹配；one_off 只看用户原话；引文跨引用行时保留用户写的部分。
- 合并 #44（#41 的修复）：纠正保底位要求无待确认更正、无冲突，且向量相似度 ≥ 0.55。
- 合并 #45（#42 的修复）：过期起算时间改为证据时间，复审清单分页。
- 11:43 合并 #46：按留出集补充"确认""改回去吧/回滚/重启/关掉""合并 dev"等说法。
- 方针：一次性授权宁可漏拦，不可误杀。

## 保留意见
- 修复后的数字都是在评估样本上调过的，乐观。诚实的留出成绩只有修复前那一行（P 0.75、R 0.23）。
- 标注者是 agent（独立评估者和执行者），不是用户。
- sample48 和 heldout160 是用户原话短句，已脱敏，仍然是私有内容。
